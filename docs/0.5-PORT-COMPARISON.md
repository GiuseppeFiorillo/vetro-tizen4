## What the Tizen 4 fork changed

| Area | Changes versus original 0.5.0 | Why it matters |
| --- | --- | --- |
| Node 4 compatibility | app/service/compat.js hardens Buffer allocation/input handling and Promise.finally; adds an actual Node 4 fixture. | Original 0.5 already has compatibility shims; the fork strengthens them rather than introducing Node 4 support from scratch. |
| App database and icons | app-registry.js, dock-catalog.js and related service queries accommodate older schemas and icon locations, including FirstScreen/Panel; remove unsupported SQLite CLI -readonly use. | Avoids empty catalogs, missing icons and failed commands on old firmware. |
| Native launcher | Adds .NET Core 2/corerun packaging alongside newer .NET, legacy TV/input commands and assembly-based AppDir resolution. | The old TV runtime cannot simply execute the modern launcher binary. corerun also resolves its application directory differently. |
| Runtime evidence and actions | Adds runtime-evidence.js and adjusts quick-wins, TV settings, privacy, HbbTV, restore and removal operations. | Uses concrete evidence and old firmware command/database layouts instead of assuming newer firmware. |
| Root-agent integration | Adds chain service adapters, authenticated root daemon integration, owner execution and debloat command adapters. | Connects the app to the old platform's root mechanism. It is separate from the upstream application's modern root path. |
| Startup and rooting tools | Adds kant-m2-root boot/supervisor tooling and adjusts rooting preflight, SDB and legacy packaging. | These are installation/infrastructure changes, not launcher UI features. They are inventoried here but the USB installer is deliberately absent from this app folder. |
| Updates and trust | Changes release-channel/key handling, unconfigured-channel UI and updater tests/docs. | The fork must not install an incompatible original release accidentally. |
| Packaging, tests and docs | WGT verification, CI/auditing, regression fixtures, release documentation; some original design/review documents removed. | Accounts for many of the 102 file differences; not all differences affect the running TV. |

## Our changes are a third layer

The fork is not the same as our tested build. Our separate 0.5 app contains six additional differing shared app/chain/dock files: the .NET 2 launcher binary; HomeGuard.cs; LegacyTvActions.cs; SystemLaunch.cs; Program.cs; and LauncherRegressionTests.cs. These hold the owner-native Netflix/YouTube launch fixes, legacy Samsung Home launch/cancellation behavior and bounded diagnostics. Our standalone dashboard, pairing, persistent root, tested Home-key database override and USB recovery watcher are additional local runtime integration.

The comparison predates the 0.7 integration; current adaptations are documented in UPGRADE-0.7.0.md.
